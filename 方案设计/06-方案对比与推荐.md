# 06 四套 UI 方案对比与最终推荐

> 前置阅读：`01-市场调研与设计启示.md`（10 款竞品）、`_shared/设计基准.md`（共用数据与规范）。
> 四套方案均由同一份数据字典驱动、同一 1440×900 画布、同一 3 张界面（主界面 / 记一笔 / 统计），因此可以逐像素横向对比。

---

## 0. 结论摘要（先看这里）

**推荐方案：A「经典财务工作台」作为唯一主骨架，并按第 6 节的配方吸收 C 的图表洞察、D 的键盘流、B 的柔和视觉配额，形成最终定稿（见 `08-推荐方案原型/`）。**

三条核心理由：

1. **记账软件的第一价值是「可信、可核对」，不是「好看」。** A 是四套里唯一做到"分类 + 时间 + 摘要 + 账户 + 金额"五列同行、任意一笔都能横向扫读对账的方案——这正是 10 款竞品里 MoneyWiz / Quicken / MMEX / Excel 模板的共同答案（见 01 文档第 4 节启示 6、8）。
2. **A 的 QML 落地成本最低。** 全部由矩形、1px 边框、8px 圆角、文字组成，无模糊、无复杂合成、图表只需 `Rectangle` 组合；反观 C 的环图/面积折线/堆叠条需要大量自绘与交互处理，B 的多层柔和阴影在 Qt Quick 里要手工堆 `MultiEffect`。
3. **A 是唯一能低成本"长成"其它方案的骨架。** 右栏换成图表与洞察卡即演进出 C 的"驾驶舱"气质；加一个 `Ctrl+K` 命令面板与自然语言速记即获得 D 的效率；把圆角与色块调柔即接近 B 的观感。反过来从 B/D 改回三栏，等于重做信息架构。

一句话落地顺序：**先做 A 的骨架与流水表（M1），再把 C 的图表搬进"概览/统计"（M2–M3），最后把 D 的键盘流做成加速器（M5）。**

## 1. 评测方法

四套方案不按"个人喜好"评，按记账软件真实使用场景加权打分（1–5 分，5 最好）。

| 维度 | 权重 | 评测口径 |
|---|---:|---|
| 可信 / 可核对性 | 25% | 单笔能否一眼核对（分类·时间·摘要·账户·金额是否同屏）；金额排版是否严格右对齐等宽；合计能否对上明细 |
| 录入效率 | 20% | 从主界面到「存好一笔」的操作步数；键盘可达性；默认值智能程度 |
| QML 落地成本（反向计分） | 20% | 组件数量、特效复杂度、图表自绘工作量、响应式列宽难度（5 = 最容易落地） |
| 首屏说服力 / 信息密度 | 15% | 1440×900 首屏能否同时回答"花了多少 / 剩多少 / 最近几笔 / 花在哪" |
| 长期使用舒适度 | 10% | 连续使用 3 个月是否疲劳；配色持久性；信息噪音 |
| 差异化 / 品牌感 | 10% | 是否一眼记住；是否与同类产品有明显区隔 |

## 4. 逐维度深挖

### 4.1 信息架构：谁能同时给"密度"和"上下文"

- **A（三栏）**：左导航管"去哪"、中栏管"看什么"、右栏管"这一笔的细节"。三者同屏，选中即联动（`ListView.currentItem` 直接驱动详情，无需二次查库）。这是 1440 宽屏的唯一最优解——MoneyWiz 与 MMEX 都验证过。
- **B（时间流 + 右栏）**：时间轴叙事感强，但右栏只能放账户/分类/趋势这类"概览"，没有"单笔详情"的容身之处；核对时必须在弹层里完成，属于"看得爽、查得慢"。
- **C（仪表盘）**：首屏全是聚合值，**看不到任何一笔流水**。日常最高频的动作是"记一笔/核一笔"，而 C 的首页没有流水位——这是它最大的结构性问题，必须跳到"流水"页才能工作。
- **D（单列）**：极简，但一屏只能看 12 条流水，且没有分类/账户的横向对齐列（靠列间距），核对效率低于 A。

**结论**：三栏是记账软件的"地基结构"，B/C/D 更适合作为三栏内某一页的"表达方式"。

### 4.2 录入路径：五套方案的"三键原则"执行度

| | 从主界面到保存 | 默认值智能 | 键盘闭环 |
|---|---|---|---|
| A | `Ctrl+N` → 金额 → 分类（↑↓/Tab）→ `Ctrl+Enter` | 上次使用账户、今天日期、本月同类统计提示、标签建议 | 完整：Tab 跳字段、数字区直连、Esc 逐层退出 |
| B | 点圆形分类 → 弹层 → 金额 → 保存 | 上次账户、常用分类、日期"今天" | 部分：数字键盘可键盘操作，但圆形分类靠鼠标 |
| C | `+ 记一笔` → 分类 10 宫格 → 金额键盘 → 保存 | 上次账户、日期 | 部分：分类宫格需鼠标 |
| D | `Ctrl+N` → 一句话「午餐 23 支付宝」→ `Enter` | **全自动解析**：分类/金额/账户/日期/摘要一次填好 | 最强：↑↓ 选择、Tab 跳字段、Enter 保存、Esc 取消 |

A 的"双栏录入"（左分类+账户+日期+备注、右金额键盘+同类统计）比 B/C 的单列弹层更省一次视线移动；D 的自然语言是效率天花板，但**解析失败率**是隐藏成本（"外卖 25 微信"能解析，"给老妈买药 48.5 支付宝 医疗"就有歧义）。

**结论**：A 的录入结构最稳，D 的自然语言应作为 A 的"加速输入框"叠加，而不是取代结构化表单。

### 4.3 统计表达：谁能让用户"看懂"而不只是"看到"

- **A**：分类排行表（名次/金额/占比/进度条）+ 分组柱 + 预算执行卡，**结论以文字行给出**（"9 月支出 ¥7,860.00 为近半年最高"、"11-12 至 11-30 还剩 19 天，建议收紧非必要支出"）。表格适合"我想核对数字"，但视觉冲击弱。
- **B**：环形图 + 分类卡片列表，观感最柔和；但占比 <5.2% 的分类在环上几乎不可见，需要图例兜底。
- **C**：四图联动（环形 / 趋势+预算基准线 / 排行条形 / 收支对比柱），**专业感与一屏说服力最强**；尤其"预算基准虚线 + 9 月超支 1,360"的表达是四套里唯一的"结论型图表"。
- **D**：大数字 + 迷你柱，克制；但用户问"餐饮占多少"时它给不出答案。

**结论**：C 的图表语言是资产，应当搬进 A 的"概览/统计"，而不是让 C 当主界面。

### 4.4 工程成本（这一项决定 MVP 能不能按期交付）

| 项 | A | B | C | D |
|---|---|---|---|---|
| 自绘标题栏 | 需要 | 需要 | 需要 | 需要 |
| 图表自绘工作量 | 低（占比条 + 柱） | 中（环形 + 卡片） | **高**（环形 + 面积折线 + 堆叠条 + 分组柱 + 交互） | 低（迷你柱） |
| 特效复杂度 | 无（1px 边框 + 8px 圆角） | 中（多层柔和阴影，QML 需 `MultiEffect` 叠加） | 中（卡片 + 网格线） | 低（描边卡片） |
| 响应式难度 | 中（列宽需断点） | 低 | 低 | 低 |
| 新增依赖 | 无 | 无 | 无（但图表 API 多） | 无 |

A 的 `设计说明.md` 已经给出可以直接抄进 `Theme.qml` 的 token 表与组件树；C 的环图、面积折线在 QML 里要么用 `Shape`/`Canvas` 手写路径，要么引入 Qt Charts（GPL/商业双轨）——这层成本对 MVP 是不划算的，但**搬到 A 的统计页上只做 3–4 个固定图表是划算的**。

## 5. 为什么不选其它三套（客观说明）

### B 卡片时间流 — 不作为主方案
- 优点真实：亲和力强、录入轻快、长期使用不疲劳，是最"想用"的一版。
- 但宽屏 1440 下，时间流单列只用到 ~780px，右栏只能放聚合信息，**信息效率约为 A 的 60%**；且核对单笔必须开弹层。
- 结论：**作为 A 的视觉配额与"轻主题"存在**——圆角、分类圆徽标、柔和投影，可用于弹层、空状态、移动/小窗布局。

### C 数据驾驶舱 — 不作为主方案
- 视觉与洞察最强，截图最"像产品"。
- 但首页无流水位（日常记账要跳转）、图表自绘成本最高、且"仪表盘式首页"会让用户每天先看 4 个 KPI 才记一笔，与"3 秒记一笔"的产品目标相悖。
- 结论：**图表语言整体搬进 A 的"概览/统计"页**；C 的 `设计说明.md` 里环形图/趋势图的实现建议可直接复用。

### D 极简速记 — 不作为主方案
- 键盘流与自然语言输入是四套里最强的效率设计。
- 但暗色单一主题不适合白天办公与低亮度显示器；分析深度最弱（统计页只有 6 根柱）；且极简单列在宽屏上信息效率偏低。
- 结论：**把 D 的"命令面板 + 自然语言速记 + 常驻快捷键条"作为 A 的加速层**，同时保留 D 的暗色作为 A 的可选主题（配色 token 见 D 的 `设计说明.md`）。

## 6. 最终配方：定稿 = A 骨架 + 三套的长处

| 取用项 | 来自 | 落在定稿的哪里 |
|---|---|---|
| 三栏骨架、工具条、KPI 五格、列结构（分类·时间·摘要·账户·金额）、日期分组、状态条 | **A** | 主界面整体 |
| 双栏录入面板（分类九宫格｜金额键盘 + 同类统计提示） | **A** | 记一笔 |
| 预算环 + 趋势面积折线 + 堆叠条 + "结论型"洞察卡（含 ↑↓ 环比） | **C** | 新增「概览」页 + 统计页顶部 |
| `Ctrl+K` 命令面板 + 常驻快捷键条 + 自然语言速记输入 | **D** | 全局加速层（不改骨架） |
| 圆形分类快捷入口、16px 大圆角、柔和投影 | **B** | 记一笔面板顶部、空状态、可选"轻主题" |
| 暗色 token（`#0E1116` / `#161A20` / 暖金 `#E4B363`） | **D** | 可选主题 |
| Design token 基线（色板/字号/圆角/间距/固定尺寸） | **A** | `Theme.qml` |

定稿已落地为可交付原型（见 `08-推荐方案原型/`）：
[主界面](08-推荐方案原型/01-主界面.png) · [概览](08-推荐方案原型/02-概览.png) · [记一笔](08-推荐方案原型/03-记一笔.png) · [命令面板](08-推荐方案原型/04-命令面板.png)，
外加 `Theme.tokens.json`（亮/暗双主题）与 `组件规格.md`（30 个组件的 QML 类型、尺寸、属性、token 依赖）。
**冲突裁决原则**（避免四套风格打架）：

1. **颜色只承担一种语义**：分类色只用于分类；绿/琥珀/红只用于预算健康度；强调色只有一个（A 的 `#2563EB`）。
2. **圆角按层级**：卡片 8px（A 基线），仅"可点的大目标"（分类圆、弹层）用 16px 以上（B 的配额）。
3. **数字永远优先**：任何页面的第一视觉焦点都是金额，装饰不得抢戏。
4. **暗色是主题，不是第二套设计**：同一套布局与 token 走两套色板，不单独设计布局。

## 8. 定稿验收清单（Design QA）

- [ ] 截图 1440×900，无滚动条、无内容被裁切
- [ ] 所有金额千分位 + 两位小数 + 等宽数字 + 右对齐；收入绿色、支出深灰、负债红色
- [ ] KPI 与流水合计、分类占比、预算执行三者可交叉对上
- [ ] 表格五列（分类·时间·摘要·账户·金额）在同一水平带内，扫读无跳行
- [ ] 预算 90.9% 呈现"进度条 + 琥珀色 + 剩余 ¥592.10 + 人话提示"四件套
- [ ] 快捷键在界面可见（状态条/命令面板/tooltip 三处键位一致）
- [ ] 空状态、加载态、错误态各有设计（新库首屏只有「记第一笔」与「导入账单」）
- [ ] 暗色主题下所有语义色仍成立（分类色不失效）
- [ ] 字号 ≥11px，关键数字 ≥13px
- [ ] 点击目标 ≥28px（窗口按钮 46×40，行高 45）

| ADR-2 | 图表 **QML 自绘**（`Shape`/`Canvas`），不引 Qt Charts | 避开 GPL/商业双轨授权；4 个固定图表自绘成本低于接入成本 | 坐标轴/刻度/交互需自己写（约 2 人日） |
| ADR-3 | 保留 **暗色主题**（D 的 token） | 夜间使用场景真实存在，成本仅一套色板 | 每个组件需走 token，禁止硬编码色值 |
| ADR-4 | 自然语言速记作为 **加速层**而非主录入 | 解析有失败率，结构化表单兜底 | 需要一套关键词规则库（V1） |
| ADR-5 | 窗口自绘标题栏（40px） | 四套方案一致选择；Windows 原生标题栏破坏设计 | 需处理拖动/双击最大化/分屏（见 07 风险 R8） |

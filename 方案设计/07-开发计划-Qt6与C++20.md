## 1. 目标与范围

### 1.1 产品目标

一款**纯本地、离线优先、启动快、录入快**的 Windows 桌面记账软件，面向个人/家庭的日常消费记录与月度预算管理。
核心体验目标：

| 目标 | 量化指标 |
|---|---|
| 启动速度 | 冷启动到可交互 ≤ 1.2 秒（1 万笔数据） |
| 录入一笔 | 键盘流 ≤ 3 秒完成（快捷键 → 金额 → 回车） |
| 流水滚动 | 1 万笔/月也保持 60 fps |
| 月度统计 | 5 万笔总量下月报生成 ≤ 150 ms |
| 数据安全 | 全本地 SQLite + 自动备份，断电不丢已提交账目 |

### 1.2 MVP 范围（必须有）

- 多账户（储蓄卡 / 电子钱包 / 现金 / 信用卡），余额自动汇总
- 收支分类（两级，内置模板 + 自定义）
- 记一笔 / 编辑 / 删除 / 撤销重做
- 流水列表：按日分组、按月筛选、搜索、按账户/分类过滤
- 月度概览：收入 / 支出 / 结余 / 预算执行
- 统计：分类结构（饼/环）、近 6 月趋势、分类排行
- 预算：总预算 + 分类预算，超支提醒
- CSV 导出；数据库自动备份（每日/退出时）

### 1.3 明确不做（V1 之前）

- 云同步、多端漫游、账号体系
- 多用户/家庭共享账本
- 银行/支付宝自动抓单（无官方开放接口，风险高）
- 发票识别、语音记账（属于 V2 探索）

### 1.4 版本节奏

| 版本 | 内容 | 预计周期（单人业余） |
|---|---|---|
| MVP | 1.2 节全部 | 4–5 周 |
| V1 | 导入支付宝/微信 CSV、附件凭证、多账本、暗色主题、快捷键全量 | +3 周 |
| V2 | 周期性账目（房租/订阅）、报表订阅导出 PDF、AI 分类建议 | 按需 |

## 2. 技术选型与论证

### 2.1 版本与工具链（已在本机核实）

| 项 | 选定 | 本机实测 |
|---|---|---|
| Qt | 6.11.1 | ✅ `C:\Qt\6.11.1`，含 `mingw_64` 与 `msvc2022_64` 两套 kit |
| 编译器 | MinGW-w64 GCC 13.10（日常）/ MSVC 2022（发布可选） | ✅ `C:\Qt\Tools\mingw1310_64` |
| 构建 | CMake ≥ 3.19 + Ninja | ✅ CMake 4.3.3、Ninja 均已安装 |
| 语言标准 | **C++20**（`CMAKE_CXX_STANDARD 20`） | ✅ GCC 13 与 MSVC 2022 均完整支持（含 `<format>`） |
| IDE | Qt Creator（已装） | ✅ `C:\Qt\Tools\QtCreator` |

**建议固定 MinGW 一套 kit 作为主开发环境**，避免两套 kit 混用导致的 DLL 路径问题（当前仓库的 build 目录是 MinGW 命名，但 PATH 里的 qmake 指向 msvc2022_64，属于典型的混用隐患）。

### 2.2 UI 技术：Qt Quick(QML) 而非 Qt Widgets

| 维度 | Qt Quick/QML | Qt Widgets |
|---|---|---|
| 视觉表现力（圆角、阴影、动画、图表自绘） | 强，`Rectangle.radius / DropShadow / ShaderEffect` | 弱，需要大量样式代理 |
| 高 DPI / 缩放 | 原生按设备无关像素 | 需手工处理 |
| 大列表性能 | `ListView` + `required property` + 复用委托，可达 60 fps | `QTableView` 配 model 也很强 |
| 开发速度（原型还原设计稿） | 快，声明式接近设计稿 | 慢 |
| 表格/多列对齐 | 偏弱，需要自己排版 | 强 |

**结论：主界面用 Qt Quick，数据表格用「ListView + 行委托」自绘**。理由是记账列表结构简单（4 列、行高固定 44–48px、无需单元格编辑），
完全可以用 ListView 做到虚拟化且比 QTableView 更贴合设计稿。若后期出现"需要冻结列 + 单元格内编辑"的强表格需求，
再局部用 `QQuickWidget` 嵌一个 `QTableView`，不推翻整体架构。

### 2.3 数据层：SQLite + 自研 Repository

- `QtSql` 的 `QSQLITE` 驱动（Qt 自带，无需第三方库）
- 开启 **WAL** 模式、`synchronous=NORMAL`、`foreign_keys=ON`
- 单写者（桌面单进程），所有写操作走事务，避免半提交
- 通过 `schema_version` 表做**增量迁移**（每版一个 migration 函数，幂等）

### 2.4 图表方案（重点决策）

| 方案 | 许可 | 评价 |
|---|---|---|
| Qt Charts | GPLv3 / 商业 | 组件成熟，但若闭源分发需商业授权；API 偏旧 |
| Qt Graphs（Qt 6.8+ 新模块） | GPLv3 / 商业 | Qt 官方新方向，QML 友好；但 6.11 仍较新，坑多 |
| **QML 自绘（Canvas / Shape / 自定义 Item）** | 无限制 | 环图、折线、柱状都简单；与设计稿 1:1；零依赖 |
| QCustomPlot | GPL / 商业 | 适合复杂科研图表，记账用不上 |

**推荐：MVP 阶段用 QML 自绘**（占比环用 `Shape` 的 arc 或 `Canvas`，趋势折线用 `ShapePath`，柱状用矩形）。
理由：记账图表类型固定、数据量小（≤12 个月 × ≤30 分类），自绘成本低于踩 Qt Charts 许可和版本坑的成本；
若将来需要交互式缩放/十字准星，再评估 Qt Graphs（并明确许可选择）。

### 2.5 其它依赖

| 需求 | 方案 |
|---|---|
| JSON 配置/导入映射 | Qt Core 内置 `QJsonDocument` |
| CSV | 自研 RFC4180 解析器（约 150 行，处理引号/换行/GBK 编码），不必引入第三方 |
| 日志 | `QLoggingCategory` + 滚动文件 |
| 安装包 | `windeployqt` 打包依赖 + Inno Setup（免费、中文友好） |
| 单元测试 | Qt Test（`Qt6::Test`），CMake `enable_testing()` + CTest |
| 崩溃收集 | Windows MiniDump 写本地文件（V1） |

CMake 分层要点：

```cmake

project(Keep_account LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 20)

set(CMAKE_CXX_EXTENSIONS OFF)

# 1) 纯 C++ 核心库：可被单元测试直接链接，不依赖 QML
qt_add_library(keep_core STATIC
    src/core/domain/Money.cpp
    src/core/data/Database.cpp
    ...
)
target_link_libraries(keep_core PUBLIC Qt6::Core Qt6::Sql)
target_include_directories(keep_core PUBLIC src)

# 2) 应用 + QML 模块
qt_add_executable(Keep_account WIN32 src/app/main.cpp src/app/AppBootstrap.cpp)
qt_add_qml_module(Keep_account
    URI Keep_account
    VERSION 1.0
    QML_FILES src/ui/Theme.qml src/ui/App.qml ...

target_link_libraries(Keep_account PRIVATE keep_core Qt6::Qml Qt6::Quick)

add_subdirectory(tests)
```

## 4. 数据模型与数据库设计

### 4.1 金额与日期约定（全局铁律）

- **金额一律用 `int64` 存「分」**（字段名 `*_cents`），禁止用 `double` 参与金额运算。
  `¥5,907.90` → `590790`。展示层统一经 `Money::format()` 输出千分位两位小数。
- 日期时间用 ISO-8601 本地时间文本 `YYYY-MM-DDTHH:MM:SS`（SQLite 可直接比较排序），
  `occurred_at` 为交易发生时间，`created_at/updated_at` 为系统时间。
- 支出/收入用 `kind` 区分，`amount_cents` **恒为正数**，符号只在展示层按 `kind` 生成。

### 4.2 表结构（建表 DDL，MVP 版）

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

-- 账户
CREATE TABLE accounts (
    id                   INTEGER PRIMARY KEY AUTOINCREMENT,
    name                 TEXT    NOT NULL UNIQUE,
    type                 TEXT    NOT NULL CHECK (type IN
                           ('savings','checking','credit','ewallet','cash','investment')),
    currency             TEXT    NOT NULL DEFAULT 'CNY',
    opening_balance_cents INTEGER NOT NULL DEFAULT 0,
    credit_limit_cents   INTEGER,                 -- 仅信用卡
    icon                 TEXT,                    -- SVG 资源名
    color                TEXT,                    -- #RRGGBB
    sort_order           INTEGER NOT NULL DEFAULT 0,
    is_archived          INTEGER NOT NULL DEFAULT 0,
    created_at           TEXT    NOT NULL
);

-- 分类（两级：parent_id 为空即一级）
CREATE TABLE categories (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    parent_id   INTEGER REFERENCES categories(id) ON DELETE RESTRICT,
    name        TEXT    NOT NULL,
    kind        TEXT    NOT NULL CHECK (kind IN ('expense','income')),
    icon        TEXT,
    color       TEXT,
    sort_order  INTEGER NOT NULL DEFAULT 0,
    is_builtin  INTEGER NOT NULL DEFAULT 0,
    is_archived INTEGER NOT NULL DEFAULT 0,
    UNIQUE (parent_id, name, kind)
);

-- 交易流水
CREATE TABLE transactions (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    kind             TEXT    NOT NULL CHECK (kind IN ('expense','income','transfer')),
    amount_cents     INTEGER NOT NULL CHECK (amount_cents > 0),
    account_id       INTEGER NOT NULL REFERENCES accounts(id) ON DELETE RESTRICT,
    to_account_id    INTEGER REFERENCES accounts(id) ON DELETE RESTRICT,  -- 仅转账
    category_id      INTEGER REFERENCES categories(id) ON DELETE RESTRICT,
    occurred_at      TEXT    NOT NULL,
    note             TEXT    NOT NULL DEFAULT '',
    payee            TEXT    NOT NULL DEFAULT '',
    external_id      TEXT,          -- 导入去重用
    created_at       TEXT    NOT NULL,
    updated_at       TEXT    NOT NULL,
    CHECK (kind <> 'transfer' OR to_account_id IS NOT NULL)
);

CREATE INDEX idx_tx_occurred   ON transactions(occurred_at DESC);
CREATE INDEX idx_tx_account    ON transactions(account_id, occurred_at DESC);
CREATE INDEX idx_tx_category   ON transactions(category_id, occurred_at DESC);

-- 标签（多对多）
CREATE TABLE tags (
    id   INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE COLLATE NOCASE,
    color TEXT
);
CREATE TABLE transaction_tags (
    transaction_id INTEGER NOT NULL REFERENCES transactions(id) ON DELETE CASCADE,
    tag_id         INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (transaction_id, tag_id)
);

-- 预算（category_id 为 NULL 表示总预算）
CREATE TABLE budgets (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    year_month   TEXT    NOT NULL,               -- '2026-11'
    category_id  INTEGER REFERENCES categories(id) ON DELETE CASCADE,
    amount_cents INTEGER NOT NULL CHECK (amount_cents >= 0),
    rollover     INTEGER NOT NULL DEFAULT 0,     -- 结余是否结转（V1）
    UNIQUE (year_month, category_id)
);

-- 设置（键值，含 UI 偏好、上次备份时间等）
CREATE TABLE settings (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);

-- 迁移版本
CREATE TABLE schema_version (
    version    INTEGER PRIMARY KEY,
    applied_at TEXT NOT NULL
);
```

### 4.3 余额与汇总的计算策略

| 数据 | 策略 | 理由 |
|---|---|---|
| 账户当前余额 | `opening_balance_cents` + `SUM(收入) − SUM(支出 ± 转账)` **实时计算**，用 3 个索引覆盖 | 单一事实来源，永不与流水不一致 |
| 月度 KPI | SQL 聚合（`strftime('%Y-%m', occurred_at)` 走索引范围扫描） | 5 万笔量级 <50 ms |
| 分类占比 | 一条 `GROUP BY category_id` + 内存算百分比 | 一次查询搞定 |
| 账户余额缓存 | V1 起可在 `accounts` 加 `cached_balance_cents`，由写入事务统一维护 | 首页秒开需要；MVP 先不做，避免不一致 |

### 4.4 迁移机制

```cpp
// core/data/Migrator.h
struct Migration { int version; QString name; std::function<bool(QSqlDatabase&)> apply; };

class Migrator {
public:
    explicit Migrator(QSqlDatabase db);
    bool migrate();                 // 逐个执行低于当前版本的迁移，事务包裹
    int  currentVersion() const;
private:
    std::vector<Migration> m_steps; // 1: 初始表结构；2: 加标签；3: 加预算 rollover ...
};
```

规则：**每次发布只新增迁移，不改历史迁移**；迁移失败整体回滚并提示用户备份。

## 5. C++20 架构分层与 QML 暴露策略

### 5.1 分层

```
┌─────────────────────────────────────────────┐
│ UI 层  QML (pages / components / dialogs)   │  只做展示与交互
└───────────────▲─────────────────────────────┘
                │ Q_PROPERTY / Q_INVOKABLE / QAbstractListModel
┌───────────────┴─────────────────────────────┐
│ 适配层 AppContext / *ListModel / *Proxy     │  薄，只做类型转换与通知
└───────────────▲─────────────────────────────┘
┌───────────────┴─────────────────────────────┐
│ 服务层 LedgerService / BudgetService / ...  │  事务边界、业务规则、撤销栈
└───────────────▲─────────────────────────────┘
┌───────────────┴─────────────────────────────┐
│ 数据层 Database / Migrator / *Repository    │  SQL、映射、连接管理
└───────────────▲─────────────────────────────┘
┌───────────────┴─────────────────────────────┐
│ 领域层 Money / DateRange / Account / ...    │  纯值类型，可脱离 Qt 单测
└─────────────────────────────────────────────┘
```

### 5.2 C++20 具体用法（用得上，不炫技）

- `concept` 约束仓储接口：`template <typename R> concept Repository = requires(R r){ { r.findById(1) } -> std::same_as<std::optional<Account>>; };`
- `std::optional<T>` 表示"查不到"，替代 `bool ok + out param`
- `std::span<const Transaction>` 传批量数据，避免 `QList` 拷贝
- `std::format` 做金额/日期格式化（GCC 13 已支持；若 MSVC 报缺，退化为 `QString::asprintf` 封装）
- 指定初始化器 `Account{.name = "支付宝", .type = AccountType::EWallet}`
- `[[nodiscard]]` 标注 `migrate()`、`save()`，防止忽略错误
- `enum class AccountType { Savings, Checking, Credit, EWallet, Cash, Investment };` 配 `Q_ENUM` 供 QML 使用

### 5.3 QML 暴露清单（MVP）

| C++ 类型 | 暴露方式 | 用途 |
|---|---|---|
| `AppContext` | QML 单例：`QML_ELEMENT` + `QML_SINGLETON` | 当前月份、当前账户、导航状态、全局命令（`recordTransaction()`） |
| `TransactionListModel` | `QAbstractListModel`，`required property` + `roleNames` | 首页流水列表（支持 `setMonthFilter` / `setAccountFilter` / `setSearchText`） |
| `AccountListModel` | `QAbstractListModel` | 侧边栏账户分组、账户下拉 |
| `CategoryTreeModel` | `QAbstractItemModel`（或扁平化 ListModel + parentId 递归） | 分类选择器、预算设置 |
| `ReportService::monthlySummary(年,月)` | `Q_INVOKABLE` 返回带 `Q_PROPERTY` 的 `Q_GADGET` | KPI 与图表数据 |
| `TableModel` | QML 直接使用 `Qt.labs.qmlmodels`? | 不需要，避免过度设计 |

**性能铁律**：

1. ListView 委托必须使用 `required property`（Qt 6 后才真正生效），减少绑定开销；
2. 行委托不超过 6 个可见元素，禁止在委托里做函数调用或正则；
3. 金额格式化在 model 的 `data()` 里算一次，QML 只绑定字符串；
4. 超过 500 条的列表必须用 `ListView` + `cacheBuffer`，禁止 `Repeater`。

### 5.4 撤销/重做

- 用 `QUndoStack`（QtGui 内置，纯逻辑可用 `QUndoCommand` 子类放在 core）
- 命令：`AddTransactionCommand`、`EditTransactionCommand`、`DeleteTransactionCommand`
- UI 暴露 `undoText/redoText`，绑定到 `Ctrl+Z / Ctrl+Shift+Z`
- 约束：撤销栈只在内存，退出清空（记账场景够用）

## 10. 当前仓库现状体检（2026-11-11 实测）

| 项 | 结论 |
|---|---|
| 目录内容 | `CMakeLists.txt`、`main.cpp`、`mainwindow.h/.cpp`（未使用）、`qml/Main.qml`、空的 `build/`、`.qtcreator/` |

| 运行 | ⚠️ 能启动窗口，但 **`Theme` 与 `App` 两个单例不存在**，运行时刷 20+ 条 `ReferenceError: Theme is not defined`，页面颜色/尺寸全部回退默认值 |
| 代码结构 | 单 target，无分层；`mainwindow.h/.cpp` 与 QML 方案重复，建议删除 |

**结论：UI 骨架方向正确（Quick + 自绘标题栏 + Theme token 的思路已经存在），缺的是 `Theme.qml`/`AppContext` 与分层架构——这正好是 M0 的任务。**

# 方案 B · 卡片时间流 — 设计说明

## 1. 定位与参考

**一句话定位**：把账本变成一条「今天花了什么」的时间流——顶部一眼看清本月花了多少，中间一张张卡片按时间往下排，想记一笔就点一个圆形分类。

参考软件与借鉴点：

| 参考 | 借鉴点 |
|---|---|
| 鲨鱼记账（移动端） | 大号本月支出数字、圆形分类快捷入口、录完即走的轻量体验 |
| Monarch Money | 柔和的卡片分组、预算进度环、克制的青绿主色 |
| Copilot Money（移动端） | 单列卡片流、分类彩色圆形徽标、留白与字号层级 |
| iOS 钱包 / 记账类 App | 16–20px 大圆角、多层柔和投影、整块可点的卡片 |

与方案 A 的根本差别：A 把一笔交易拆成一行表格的五列；B 把一笔交易包成一张卡片，一屏只强调 3–4 笔，用留白和圆角换取「愿意每天打开」的手感。二者共享同一套数据口径，但信息密度差约 2.5 倍。

分区职责：

1. **标题栏 40px**：极简——应用名 + 账本名 + 三个窗口热区，让位给下面的 hero。
2. **顶部导航 64px**：品牌标识 + 5 个横向一级入口（概览/流水/统计/预算/账户，激活项为青绿药丸底）+ 搜索圆形按钮 + 用户头像 + 珊瑚色「+ 记一笔」主按钮（这是全局唯一高饱和按钮）。
3. **hero 区 208px**：深青绿渐变卡，左侧大号「¥5,907.90」+ 紧张态提示 chip（预算已用 90.9%）+ 收入/结余 chip + 一行元信息；右侧 128px 的预算进度环（珊瑚色弧线表示紧张）+ 环下「剩余 ¥592.10 / ¥6,500.00」。**一屏最大字号留给本月支出**，这是本方案的主张。
4. **分类快捷录入条 108px**：8 个 52px 圆形按钮（餐饮/交通/购物/住房/娱乐/日用/医疗/更多），每个带淡色底 + 分类色文字 + 12.5px 文字标签。点一下即带分类进入录入，是本方案的核心快捷路径。
5. **时间轴**：左侧 46px 时间刻度 + 26px 竖线轨道（线上 11px 圆点，当笔最新用珊瑚色、其余青绿、历史日期用灰色）+ 右侧 16px 圆角白卡（分类圆徽标 40px / 摘要 15px 半粗 / 账户·备注 12.5px 次要 / 金额 17px 右对齐）。日期分节头显示「今天 11 月 11 日 周三」与当日小计。
6. **右栏 560px**：账户卡（5 个账户 + 净资产）、本月分类卡（前 3 类相对条形）、近 6 个月支出卡（按最大值等比的小柱图 + 当前月高亮）。

统计页（03-统计）：`收支去向` 标题行 → 左 780px「支出结构」环形图卡（10 段环 + 双列图例，中心显示合计 ¥5,907.90）+ 右 560px「本月预算」卡（超大数字 + 14px 珊瑚渐变进度条 + 2×2 迷你统计）→ 左「分类支出」2×3 卡片网格（圆形徽标 + 分类 + 占比 + 相对条形 + 金额）+ 右「近 6 个月支出」柔和柱图。**刻意不做仪表盘式的多图表堆叠**，保持「卡片 + 一个主图」的克制。

记一笔（02-记一笔）：主界面压暗 `rgba(18,26,36,.52)`，居中浮出 560×856 的大圆角浮层（28px 圆角，手机全屏 sheet 的桌面版）：标题 + 支出/收入/转账分段 → 浅灰金额区（`¥23.00` 44px）→ 3×4 数字键盘（54px 键、14px 圆角）→ 圆形分类横条（选中项 2.5px 青绿描边环）→ 付款账户药丸（上次使用高亮）→ 日期与备注（备注框为聚焦态，带青绿光标）→ 常用备注标签 → 珊瑚色「保存这一笔」大按钮。

## 4. 交互与快捷键设想

| 快捷键 / 手势 | 行为 | 备注 |
|---|---|---|
| `Ctrl + N` | 打开「记一笔」浮层 | 与 A 方案一致，保证切换方案时肌肉记忆不变 |
| 直接敲数字 | 在浮层任意位置输入数字即进入金额编辑 | 不必先点金额区，是「3 秒记一笔」的关键 |
| `Tab` / `Shift + Tab` | 在 分类圆条 → 账户药丸 → 日期 → 备注 之间切换 | 焦点项显示 2.5px 青绿描边环 |
| `Ctrl + Enter` | 保存并关闭 | `Ctrl + Shift + Enter` = 保存并再记一笔 |
| `Esc` | 关闭浮层（有改动时二次确认） | 逐层回退 |
| `Ctrl + ←` / `Ctrl + →` | 切换月份；hero 数字与时间流整体刷新 | `Ctrl + T` 回到本月 |
| 点圆形分类 | 以该分类直接开新的一笔（金额待填） | 快捷录入条的核心价值 |
| 点时间轴卡片 | 卡片原地展开，显示备注 / 编辑 / 删除 / 复制 | 不使用右侧抽屉，保持「流」的连续性 |
| 点 hero 的预算环 | 跳到「预算」页并聚焦本月预算 | 环本身即入口 |
| `Ctrl + K` | 打开全局搜索（浮层形式，搜索足迹覆盖摘要/备注/金额） | 顶栏搜索按钮同源 |
| 鼠标滚轮 / 触控板 | 时间流纵向滚动，日期分节头吸顶 | 滚动时 hero 渐隐（视差）|
| `Ctrl + Z` | 撤销最近一次删除 / 编辑 | 与卡片内「撤销」提示条联动 |

补充反馈设计：

- 保存成功后，新卡片以「淡入 + 上移 8px」进入时间流，并在 hero 数字上做一次 600ms 数字滚动。
- 预算环超过 85% 时环色由青绿渐变过渡到珊瑚色；超过 100% 时环变满、数字变珊瑚色并出现「已超支」chip。
- 圆形分类按钮按下时有 `scale 0.96` 的回弹、抬起回到 1.0（120ms，OutQuad）。

## 5. 优点 / 缺点 / 最适合的人群

**优点**

1. **降低打开成本**：大数字 + 卡片 + 大留白，一屏只有 3–4 笔，视觉压力远低于表格，更容易形成「每天看一眼」的习惯。
2. **录入摩擦最低**：圆形分类快捷条 + 直接敲数字 + 大键盘，一双眼睛不用在表单里找字段，符合「3 秒记一笔」的目标。
3. **情绪友好**：预算环与超支提示用珊瑚色而非刺眼红，紧张但不斥责；圆角与柔影让「看花钱记录」这件事不那么有负罪感。
4. **时间感强**：竖线 + 时间刻度天然表达「今天 / 昨天 / 前几天」，比按日期分组的表格更符合人对消费的记忆方式。
5. **与移动端同构**：单列卡片、底部大按钮的思路可直接平移到手机 / 平板版本，跨端一致性好。

**缺点**

1. **信息密度低**：一屏 4 笔 vs 方案 A 的 11 笔；要做「上月对账」「找某笔 268 元」这类任务效率明显更低。
2. **不适合复杂账本**：家庭多成员、多账套、带预算科目与对账的场景，卡片流承载不了那么多维度。
3. **纵向无限增长**：流水多时依赖滚动，缺少表格那种「一眼扫完全月」的把握感。
4. **视觉成本高**：多层柔和投影 + 渐变 + 大量圆角在低端机器 / 远程桌面下需要烘焙成图片，实现成本高于 A。

**最适合的人群**

25–35 岁、以「随手记 + 月度看趋势」为主、几乎不做逐笔对账的年轻上班族与学生；也适合作为产品的默认视图，让重度用户再切到「表格视图」。不适合会计型用户与需要审计追溯的家庭账本。

## 6. QML 实现要点与风险

### 6.1 建议的组件结构

```
ApplicationWindow (FramelessWindowHint)
└─ ColumnLayout
   ├─ TitleBarB.qml          40px
   ├─ AppHeader.qml          64px：tabs + 搜索 + CTA
   └─ RowLayout
      ├─ ColumnLayout（主列 780）
      │  ├─ HeroCard.qml        208px：渐变 + 大数字 + BudgetRing
      │  ├─ QuickEntryStrip.qml 108px：横向 8 个圆钮
      │  └─ TimelineList.qml    ListView(section) + 时间轨道 delegate
      └─ ColumnLayout（右栏 560）
         ├─ AccountsCard.qml / CategoryCard.qml / TrendCard.qml
```

### 6.2 关键技术点

- **预算进度环**：用 `Shape` + `PathAngleArc`（QtQuick.Shapes，内置模块）画弧，`sweepAngle: 360 * ratio`，再用 `ShapePath` 做底轨。比 `Canvas` 更省 CPU，且能直接做 `Behavior on sweepAngle` 动画。
- **hero 渐变**：`Rectangle { gradient: LinearGradient { GradientStop… } }`，成本极低；hero 右上角的柔光圆用一层 `opacity: .07` 的白色 `Rectangle` + `radius: width/2` 即可，不要用模糊。
- **柔和多层投影**：Qt 6 推荐 `MultiEffect { shadowEnabled: true }`（QtQuick.Effects）。**注意**：每个实例都有一次离屏渲染开销，列表里 60+ 张卡片逐张开阴影会掉帧——正确做法是把卡片阴影烘焙成一张 9-patch PNG（`BorderImage`）或用 `MultiEffect` 且 `layer.enabled: false` 的静态代理。
- **圆形徽标**：`Rectangle { radius: width/2; color: 分类色 }` + 白色 `Text`，无需图片。
- **时间轴竖线**：一个绝对定位的 `Rectangle { width: 2 }` 贯穿 ListView 内容区（放在 `contentItem` 里），圆点用每行 delegate 内的 `Rectangle { radius: width/2; border.width: 2.5 }`，比用图片简单且随滚动正确。
- **时间流分节**：`ListView.section.property: "dateKey"` + 吸顶 `section.delegate`（`stickyHeader` 效果的替代：把分组头放在 `header` 并用 `contentY` 计算 sticky 位置）。
- **数字输入**：`TextField { inputMethodHints: Qt.ImhFormattedNumbersOnly }` 或自定义键盘面板；`font.features: { "tnum": 1 }` 保证金额列不跳动。
- **浮层**：`Popup { modal: true; closePolicy: Popup.CloseOnEscape }` + 背景 `Rectangle { color: "#0F1218"; opacity: .52 }`，圆角靠 `background: Rectangle { radius: 28 }`。

### 6.3 风险与成本

| 项 | 风险等级 | 说明与对策 |
|---|---|---|
| 多层柔和投影 | **高** | 视觉上最讨喜，也最容易掉帧。对策：卡片阴影统一烘焙为 9-patch 位图，或用 `MultiEffect` 但限制同屏实例数（≤15） |
| 圆角裁剪 + 阴影叠加 | 中 | `radius` + 阴影同时存在时需 `layer.enabled: true` + `OpacityMask`，嵌套多层会显著增加 GPU 开销；建议卡片内部不再套第二个圆角容器 |
| 渐变 + 大数字 | 低 | `LinearGradient` 与 `Text` 均为原生能力，无风险 |
| 环形图 10 段 | 中 | 统计页圆环有 10 个 `PathAngleArc`，每段都需精确的 start/sweep；建议把 10 段色值 + 占比放进 model，用 `Repeater` 生成，避免硬编码角度 |
| 数字滚动动画 | 中 | hero 数字变化需要「滚动/淡入」效果，建议用两个 `Text` 交叉淡入，而不是逐位滚动（逐位在中文货币格式下难对齐） |
| 分类圆形快捷条 | 低 | `ListView { orientation: Horizontal; spacing }` + 8 个 delegate，无性能问题 |
| 1100px 以下窗口 | 中 | 主列 780 + 右栏 560 是硬宽度，窄窗口需把右栏折叠成抽屉；建议窗口最小宽度定为 1180 |
| 输入法 / 中文备注 | 低 | 备注框需支持中文输入法候选窗，注意 `TextField` 在自绘窗口下的候选窗定位（Qt 6 已较好支持） |

**总体结论**：方案 B 的视觉收益集中在「圆角 + 柔影 + 渐变 + 大字号」四件事上，其中只有**多层柔和投影**是真正的性能风险点，需要提前用 9-patch 或静态代理方案规避；其余均可用 Qt Quick 内置能力低成本还原。若团队追求「一周内出可运行版本」，建议先落 A 的骨架、再逐屏替换成 B 的视觉语言。

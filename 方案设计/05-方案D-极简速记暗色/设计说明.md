> 设计稿：`01-主界面.html/.png`　`02-记一笔.html/.png`　`03-统计.html/.png`（1440×900 自绘标题栏窗口，单文件自包含）

## 1. 定位与参考

**一句话定位**：把「记一笔」压缩成一次键盘输入——打开即输入、回车即保存，其余时间只留干净的流水和大数字。

| 参考 | 借了什么 |
|---|---|
| Raycast | 命令面板形态、`Ctrl + K` 入口、底部键帽提示条、深色悬浮层 |
| Things 3 | 单列居中、克制留白、极细分割线、只有文字和金额的行 |
| Obsidian | 深色底 + 单一强调色，绝不使用第二强调色 |
| Linaria / Linear 类文本流 | 超大金额数字、`tabular-nums` 对齐、标题字号以外的全部弱化 |

**强调色**：暖金 `#E4B363`（全案唯一强调色，亮档 `#F2C97D`、深档 `#C08A3E`）。
**与另外三案的差异**：A 是表格、B 是卡片时间流、C 是图表驾驶舱、**D 是暗色极简键盘流**（无卡片边框、无多栏、无环形/折线图）。

- **标题栏 40px**：深一档的 `#0B0E13`，左侧金色方块 logo + 应用名 + 账套，右侧三个 46×40 热区。
- **导航 48px**：只有三个文字项，选中项用 2px 金色下划线；右侧 `Ctrl K 命令` 是全案唯一的入口提示（也是唯一的「按钮」）。
- **大数字区 120px**：今日支出 / 本月支出并排，44px 数字 + 竖向 1px 分割线；数字用「小货币符 + 大整数 + 小小数」的三段式，视觉重量集中在整数位。
- **预算条 54px**：一行读完预算 / 已用 / 剩余，4px 金色渐变细条，上下各一条极细分隔线，不用卡片包裹。
- **本月结构 104px**：一条 6px 四段比例条（金 → 深金 → 棕金 → 灰），下面 4 列图例（名称 / 金额 / 占比），用单色金阶而不是 10 种彩色——这是 D 与 C 最大的气质差异。
- **流水 472px**：表头 26px + 12 行 × 35px，单行五列（时间 / 摘要 / 分类 / 账户 / 金额），**没有图标框、没有分类色块**，只有文字与金额；收入行金额为金色，选中行左侧 2px 金条 + 5.5% 金色透明底。
- **键帽条 44px**：`↑↓ 选择` `Enter 保存` `Esc 取消` `Ctrl K 命令面板` + 右侧同步状态，随时提醒这是键盘流软件。

**02 记一笔**：主界面压暗至 74% + 720px 命令面板，分三段——
① **已解析区**（上）：`已解析为 1 笔支出 · 5 个字段已自动填充` + 5 个 chips（`分类·餐饮` `金额·¥23.00`(金色高亮) `账户·支付宝` `日期·11-11` `摘要·午餐 · 沙县小吃`）+ `同类最近：11-04 外卖 · 麻辣烫 −¥32.80` + 右侧 `保存后本月支出 ¥5,930.90 · 预算 91.2%` 的预演结论。
② **原始输入区**（下）：带金色焦点环的输入框，原文「午餐 23 支付宝」+ 2px 闪烁光标，右侧 `Esc`。
③ **键帽条**：选择 / 编辑字段 / 保存 / 取消 + 金色 `保存 Enter` 主按钮。

**03 统计**：**刻意不堆图表**。从上到下 = 月份切换器（`J K` 切月）+ 56px 大数字 + 6 根迷你柱（当前月金色、上方只标它自己的数值）+ 最高/最低/均值一行结论 + 收入/结余/预算剩余三栏数字 + 6 行 4px 细条排行 + 快捷键提示。全页只有柱条和细条两种图形元素，没有网格、没有坐标轴、没有图例框。

## 4. 交互与快捷键设想

1. **`Ctrl + K`**：命令面板（记一笔 / 跳到某月 / 搜索流水 / 导出 / 设置），面板内即时搜索。
2. **`N` / `Ctrl + N`**：直接进入「记一笔」，光标已在输入框，**开箱即可打字**（不停留在空表单）。
3. **`Enter`**：保存当前解析结果；**`Shift + Enter`**：保存并继续记下一笔（连续记账不打断）。
4. **`Esc`**：关闭面板 / 取消本次输入，回到上一屏。
5. **`↑` / `↓`**：在流水列表或 chips 之间移动选择；选中行左侧出现 2px 金条。
6. **`Tab` / `Shift + Tab`**：在 chips 之间跳转编辑单个字段（例如只改分类，不动金额）。
7. **`J` / `K`**：统计页切换月份；**`T`**：切换维度（分类 / 账户 / 标签）。
8. **`Ctrl + Z`**：撤销上一笔（5 秒内直接撤销）。
9. **`/`**：聚焦搜索并过滤流水；**`G`**：跳回「今日」。
10. **窗口按钮**：46×40 热区，关闭 hover 变 `#E81123` 白字。

> 设计原则：**任何操作都有键盘路径**，每个页面底部常驻键帽条，随时告诉你「现在能按什么」。

## 5. 优点 / 缺点 / 最适合人群

**优点**
- 记一笔路径最短：`N` → 打字 → `Enter`，三次交互完成，键盘用户效率最高。
- 视觉噪音全案最低：无卡片框、无多栏、无图例，注意力只在数字和文字上。
- 自然语言 + chips 把「随手记」与「结构化落库」统一：输入可以随意，存库一定规整，且 chips 是可点击的纠错入口。
- **QML 实现成本最低**：几乎全是 `Rectangle` + `Text` + 少量条状图，没有环形、没有坐标轴、没有渐变遮罩（金渐变用原生 `Gradient` 即可）。
- 与 A/B/C 气质一眼区分（暗色 / 单列 / 无边框 / 键盘）。

**缺点**
- 没有图表深度：想看结构、趋势必须切到统计页，且统计页刻意克制，分析能力弱于 C。
- 暗色在强光环境（户外、亮办公室）可读性差，应提供浅色主题切换。
- 自然语言解析出错时纠错成本偏高：要 `Tab` 逐个字段改，比表单直选慢。
- 单列 820 在大屏上浪费左右各 310px，1440 以上分辨率利用率低。
- 键盘流有隐性学习门槛，鼠标用户首次上手会找不到「记一笔」入口（靠 `N` 与底部键帽条缓解）。

**最适合**：Raycast / 终端 / Vim 型重度键盘用户；每天记 3–10 笔、讨厌填表单的上班族；「只想记完就走、不想看见记账软件」的人。不适合需要月度复盘报表、家庭多人对账的场景——那是 C。

## 6. QML 实现要点与风险

| UI 元素 | QML 实现方案 | 成本 | 风险 |
|---|---|---|---|
| 单列 820 居中 | `Item { width: 820; anchors.horizontalCenter: parent.horizontalCenter }` + `Column` | 极低 | 无 |
| 大数字三段式 | 一个 `Row` + 三个 `Text`（货币符 26 / 整数 44 / 小数 26），`font.features:{"tnum":1}` | 极低 | 需保证三个 Text 的 baseline 对齐：`Row { anchors.baseline }` 或统一 `verticalAlignment` |
| 命令面板 | `Popup { modal:true; closePolicy: Popup.CloseOnEscape }` + 自定义遮罩 `Rectangle{ color:"#B3080A0E" }` | 低 | 不要用默认 `dim`（颜色与设计稿不符）；`Popup` 圆角需 `background: Rectangle{radius:14; clip:true}` |
| 光标闪烁 | `Rectangle{width:2} + SequentialAnimation on opacity`（1.1s，step-end 等效 → 用 `Keyframe` 或 `PropertyAnimation` 往返） | 极低 | 不要用 Timer 链；截图/录屏时需要能暂停动画 |
| chips | `Flow { spacing:7 }` + `Repeater` + `Rectangle{radius:8}` | 极低 | 中文摘要 chip 宽度不一，`Flow` 自动换行即可 |
| 迷你柱 | `RowLayout` + `Repeater` + `Rectangle{ radius:3; Layout.preferredWidth:32 }`，高度 = 值/最大值 × 62 | 极低 | baseline 必须统一（`Layout.alignment: Qt.AlignBottom`） |
| 细条排行 | 底轨 `Rectangle{#1A1F26}` + 内部金渐变 `Rectangle` | 极低 | 金渐变用原生 `Rectangle { gradient: Gradient { GradientStop{...} } }`（Qt 6 原生，**不需要** Qt5Compat.GraphicalEffects） |
| 键帽 | `Rectangle{border.width:1; border.bottomWidth 效果用两层 Rectangle}` | 极低 | QML 的 `Rectangle` 不支持单边 border，键帽底边加粗用叠一个 2px `Rectangle` 实现 |
| 暗色层级 | **1px `rgba(255,255,255,.07)` 描边替代阴影** | 极低 | 这是暗色主题最关键的一条：用 MultiEffect 做暗色阴影几乎看不见还费性能 |
| 键盘导航 | `FocusScope` + `Keys.onPressed`；列表用 `ListView{currentIndex}`，选中态绑定 `ListView.isCurrentItem` | 低 | `Popup` 内需要 `focus: true` + `activeFocusOnTab`，否则方向键会被外层列表截走 |
| 自然语言解析 | C++ 侧 tokenizer：金额正则 → 分类词典 → 账户词典 → 日期词，最长匹配优先，返回 `QVariantMap` 给 QML 渲染 chips | 中（本方案唯一的中等成本项） | ① 中文无空格分词：「午餐23」需先切数字；② 「支付宝/余额宝」「微信/微信零钱」需最长匹配；③ 解析失败要有兜底（回落为普通表单），不能出现空 chips |
| 金额等宽 | `font.features:{"tnum":1}`（Qt 6.5+） | 低 | 若字体不支持 `tnum`，退化为 `Consolas`，视觉会变 |
| 图标 | `Shape{ShapePath{PathSvg{path:"M…"}}}`（描边式，贴合 `stroke 1.6`） | 低 | QML 不能直接渲染内联 SVG 文本，必须转 `PathSvg` 或预渲染资源 |

**其它落地建议**
- 主题色要做成单例 `Theme { readonly property color accent }`，暖金/青柠二选一只改一个值；否则散落的 `#E4B363` 无法切换。
- 暖金在低亮度 OLED 屏上偏土黄，建议提供 `#F2C97D / #E4B363 / #C08A3E` 三档并在设置里让用户选亮度。
- 流水行用 `ListView` 而不是 `Repeater`（17 笔→上千笔时性能差异明显）；行高固定 35 可开 `reuseItems`。
- 60fps 风险点只有一个：命令面板的遮罩如果做成「模糊底」会触发全屏离屏渲染——**本方案刻意不做毛玻璃**，只用纯色半透明遮罩。
- 建议最小窗口 1100×700；窄于 1100 时单列宽度改为 `Math.min(820, parent.width - 80)`。

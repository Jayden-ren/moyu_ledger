## 1. 调研判据

- **录入路径长度**：从主界面到"这一笔存好"要几次点击。记账是高频动作，路径长度近乎生死线。
- **首屏信息密度**：1440x900 内不滚动能否看到"本月花多少、预算还剩多少、最近几笔"。
- **实现成本**：QML 落地，依赖重度模糊、多层嵌套蒙版、大规模实时重排的效果一律降权。

## 2. 逐款竞品分析

### 2.1 钱迹（Windows 桌面端典型，Qt 实现）

- **定位**：轻量、无广告、跨端同步的个人记账工具。
- **目标用户**：有稳定记账习惯、反感理财推销的年轻上班族。
- **主界面结构**：顶部账本与月份切换；中部支出 / 收入 / 结余三枚数字卡；下方按日分组流水（日期吸顶，行内"分类徽标 + 摘要 + 账户小字 + 右对齐金额"）；"记一笔"为常驻入口；独立图表页给分类环形图与月度趋势。
- **信息架构**：账本 → 账户 → 分类 三轴正交，流水是一等公民，其余视图都是流水的投影。
- **优点**：录一笔 3-4 次点击；支付宝/微信账单导入强；数据模型干净、易迁移。
- **缺点**：桌面端沿用移动端密度，宽屏留白多；报表维度偏少（推测）。
- **可借鉴**：① 分类九宫格 + 数字键盘同屏，桌面端把主键盘数字区直接映射金额（A/B/D）；② 按日分组的日期吸顶分隔条（A/B）；③ 账户用小色点标记，不占列宽（A/C）。

### 2.2 随手记

- **定位**：功能全家桶式记账 + 理财内容社区。
- **目标用户**：家庭记账、需要多账本（生意 / 装修 / 旅游）与多人共享的用户。
- **主界面结构**：底部四 Tab（记账 / 图表 / 发现 / 我的）；记账页顶部预算进度条，中部大号"记一笔"，下方流水；图表页为收支、分类、趋势三段式。
- **信息架构**：用**场景化账本模板**替代通用分类，降低选择成本，代价是数据被模板锁定。
- **优点**：模板丰富、报表多、家庭共享成熟。
- **缺点**：功能膨胀、首页被运营位挤占；免费版有广告；科目体系复杂。
- **可借鉴**：① 首启用"个人 / 家庭 / 旅行"模板一键决定分类集（A/B）；② 预算进度条常驻流水区顶部而非藏进统计页（A/C）；③ 反面教材：首屏不该出现资讯流。

### 2.3 鲨鱼记账

- **定位**：极简移动记账，主打"三秒记一笔"。
- **目标用户**：只想快速记流水、不看复杂报表的轻度用户。
- **主界面结构**：白底；顶部本月支出大数字 + 环比箭头；中部横向滚动分类快捷入口；下方卡片式流水（左分类徽标 + 摘要 + 时间，右金额）；图表页只有饼图与柱状图。
- **信息架构**：决策收敛到"分类"一个必填项，账户可选填——用减少必填换速度。
- **优点**：视觉柔和、认知负担低、单手流畅。
- **缺点**：不支撑多账户对账；报表深度不足，长期使用洞察弱。
- **可借鉴**：① 顶部"大数字 + 环比箭头"直接给结论（B）；② 16-20px 大圆角 + 柔和投影建立层次（B）；③ 双字分类徽标 + 正负色金额，扫读快于纯文字（B/D）。
### 2.4 MoneyWiz 4

- **定位**：跨平台（macOS / iOS / Windows）专业级个人与小企业财务软件，订阅制，支持银行直连。
- **目标用户**：多账户、多币种、有投资与预算需求的进阶用户。
- **主界面结构**：经典三栏——左侧导航（账户树 / 预算 / 报表 / 定期交易），中间 Register 表格（日期、账户、分类、收款人、金额、状态），右侧 Inspector 详情面板；顶部工具栏放搜索与筛选。
- **信息架构**：复式记账被简化为"余额由流水实时推算"，预算、定期交易、报表都是同一模型的不同视图，不存冗余。
- **优点**：三栏在 1440 宽屏效率极高；单元格行内编辑；深色模式完整。
- **缺点**：概念多（预算 / 计划 / 对账），新手陡峭；价格高；国内账户体系适配弱。
- **可借鉴**：① 三栏骨架（导航 / 表格 / 详情）是**方案 A 的母本**；② 对账状态用图标列而非文字列，省一列宽；③ 编辑放右侧详情面板，避免模态框打断连续核对（A）。

### 2.5 Money Manager Ex（开源，C++/wxWidgets + SQLite）

- **定位**：免费开源的桌面个人财务管家，技术栈与本项目最接近。
- **目标用户**：重视数据本地化、要求自由导出的用户。
- **主界面结构**：左侧 Navigation 树（Dashboard / Accounts / Favorites / Repeating / Reports / Assets）+ 右侧内容区；Dashboard 由小卡片组成（账户余额、最近交易、分类汇总）；报表页是"参数表单 + 结果表格"。
- **信息架构**：导航树 + 内容区，功能全平铺不隐藏；报表为参数化表格而非可视化图表。
- **优点**：SQLite 单文件、备份与导入导出成熟；报表可参数化；有预算与定期交易。
- **缺点**：界面停留在 2010 年代审美，控件密集、留白失控；缺状态反馈。
- **可借鉴**：① 借其表结构思路：账户、分类 parent_id 层级、定期交易模板、汇率表（全方案底层）；② 报表页"可折叠筛选栏 → 出表 → 导出"三段式（A/C）；③ 反面教材：不要全功能平铺导航，应"常用五项 + 更多"。

### 2.6 GnuCash（开源，GTK，复式记账）

- **定位**：真正的复式记账软件，接近会计工具。
- **目标用户**：有会计背景、需要借贷平衡与多币种的投资人 / 小企业。
- **主界面结构**：双窗口模型——账户树窗口按资产 / 负债 / 权益 / 收入 / 费用五类分层，双击账户打开其 Register 账簿窗口；账簿为电子表格式，每行一笔，含"转账账户"列，拆分交易展开为多行借贷。
- **信息架构**：科目层级 + 借贷必平衡，资产负债表与损益表由科目树推导。
- **优点**：数据严谨、多币种、定期交易、报表口径专业。
- **缺点**：术语门槛极高；交互古老；无预算可视化，新手劝退。
- **可借鉴**：① 账户按资产 / 负债 / 收入 / 费用四组分层，正是"净资产"的天然来源（A/C）；② 拆分交易用可展开子行表达，比记两笔更贴真实场景（A）；③ 绝不把借贷术语暴露给普通用户。

### 2.7 YNAB

- **定位**：方法论驱动的"信封预算"（给每一块钱分配工作），订阅制 Web + 移动。
- **目标用户**：被预算焦虑驱动、想改变消费习惯的用户。
- **主界面结构**：顶部三 Tab（预算 / 账户 / 报表）；预算页是一张大表格——左侧分类分组树，右侧三列"已分配 / 活动 / 可用"，行内直接改数；页面顶端"待分配"超大数字；每行"可用"带水平进度条。
- **信息架构**：预算优先于流水，账目服务于预算；行内编辑 + Tab 流转是核心交互。
- **优点**：单一"可用余额"指标驱动全部决策；键盘效率高；色义严格（绿健康 / 黄紧张 / 红超支）。
- **缺点**：方法论学习成本高；与国内账户体系不适配；无多账本。
- **可借鉴**：① "可用 = 预算 − 已花"的行内进度条 + 三态色，正好对应本产品 90.9% 已用的紧张态（A/C）；② 顶端超大"待分配"数字作页面锚点（B/C）；③ 表格内 Tab 跳格、Enter 编辑、Esc 取消（A/D）。

### 2.8 Quicken Simplifi

- **定位**：订阅制轻量个人财务（Web + 移动），主打账户自动聚合与消费计划。
- **目标用户**：希望自动分类、少手工录入的北美中产。
- **主界面结构**：Dashboard 卡片网格（消费计划、Top 分类、关注清单、净资产曲线）+ 左侧导航（交易 / 预算 / 报表 / 投资）。
- **信息架构**：关注清单（Watchlist）驱动首页——用户先声明"我关心什么"，再决定首页放什么。
- **优点**：首页可自定义；图表轻量但有效；异常支出提醒细。
- **缺点**：强依赖银行直连，国内无法落地；深度定制弱。
- **可借鉴**：① 允许把 3 个最关心的指标钉到首页（C，本项目简化为固定四卡）；② 卡片统一"标题 + 主数字 + 微图表"三段式（C）。

### 2.9 Monarch Money / Copilot Money

- **定位**：Monarch = 家庭财务协作（Web + 移动）；Copilot = 苹果生态精品，AI 辅助分类。
- **目标用户**：重视设计质感与家庭共享的年轻中产（北美）。
- **主界面结构**：Monarch 为顶部大类目 Tab + 卡片流 + 预算环形图；Copilot 为逐月滚动流——每月大标题、当月支出超大字号、环形分类图、按日分组的交易卡，滚动时月份吸顶（部分细节推测）。
- **信息架构**：时间轴是核心轴，横向切月份、纵向切分类，靠滚动而非点击获取全貌。
- **优点**：设计语言统一（大字号数字、克制配色、微动效）；层级靠字号与留白而非分隔线。
- **缺点**：功能深度不及 YNAB；Copilot 仅苹果生态且均需订阅。
- **可借鉴**：① 超大字重数字 + 小字灰标签的对比排版，是"一眼看清"的最短路径（B/C/D）；② 月份吸顶 + 按月分段的纵向时间流（B）；③ 月末"月度回顾"卡片把数据变成激励（B）。

### 2.10 Excel / 表格模板类记账

- **定位**：用户自建模板，公式即业务逻辑。
- **目标用户**：Excel 熟练、追求完全自定义与数据主权的用户。
- **主界面结构**：一张纵向长表（日期 / 分类 / 金额 / 备注）+ 若干数据透视表与图表工作表。
- **优点**：对老手几乎零学习成本；完全自由；无数据锁定。
- **缺点**：无输入校验与提醒；对账靠手工；移动端难用；公式一改全崩。
- **可借鉴**：① 表格即界面——冻结首行、紧凑列宽、行斑马纹、数字右对齐、千分位，这套"熟悉感"是方案 A 的对标（A）；② "行 = 分类、列 = 月份"的交叉表最省认知（A/C）；③ 反面教材：别让用户先映射字段或写公式才能看报表。

## 4. 12 条设计启示

|---|---|---|
| 1 | 预算紧张态必须被看见：90.9% 已用不能只给百分比，要"进度条 + 变色 + 剩余金额 + 一句人话提示"。 | A / C |

| 5 | 一屏只主张一件事：A 密度、B 时间流、C 图表、D 命令入口，不要互相抢注意力。 | 四套通用 |
| 6 | 数字排版即产品：等宽数字、右对齐、千分位、两位小数、正负色，收益高于任何装饰。 | 四套通用 |

| 8 | 用宽度换信息：1440 窗口发挥三栏或双栏，不要把移动端单列等比拉宽。 | A / C |
| 9 | 首体验是空状态：新用户第一屏只有"导入账单"或"记第一笔"两个出口。 | A / B |
| 10 | 编辑不打断上下文：核对时用右侧详情面板，只有新增才用模态遮罩面板。 | A |
| 11 | 图表要能读出结论：标题直接写结论（"住房占本月支出 54.2%"），图只是证据。 | C |
| 12 | 暗色不是反色：用亮度分层（#0E1116 底 / #161B22 面板 / #232B36 悬浮）+ 单一强调色。 | D |

## 5. Qt6 桌面记账软件可复用交互清单

### 5.1 表格虚拟化（性能红线）

- C++ 侧 `QAbstractTableModel` + `QSortFilterProxyModel`，不要用 QML 大 JS 数组模型。
- `TableView` 开 `reuseItems: true`，**行高固定**（32-36px 配 13px 正文），行高可变会摧毁复用。
- 分页：SQLite `LIMIT/OFFSET` 按月预取 + `canFetchMore/fetchMore`，内存只留可视区上下各约 2 屏（≈200 行）。
- delegate 里不放 `ShaderEffect`、多重投影、深层 `Loader`；金额列用单行 `Text`。

### 5.2 快捷键体系

`Ctrl+N` 记一笔（全局最高优先）｜`Ctrl+F` 搜索流水｜`Ctrl+K` 命令面板｜`Ctrl+1..5` 切主导航｜`Ctrl+S` / `Esc` 保存 / 取消录入｜`Delete` 删除（二次确认）｜`Ctrl+Z` 撤销（`QUndoStack`，误删是记账软件头号事故）。原则：快捷键必须"看得见"——菜单、tooltip、命令面板标注同一组键位。

### 5.3 命令面板（D 方案核心，其余方案做加速器）

- 单输入框 + 可执行项，模糊匹配按"子序列 + 前缀加权 + 近期使用加权"（输入 jyb 命中"记一笔"）。
- 条目统一"动词 + 对象"：「记一笔」「跳转 · 统计」「筛选 · 本月餐饮」「导出 · 本月 CSV」。
- 键盘闭环：↑↓ 选择、Enter 执行、Esc 关闭；C++ 侧维护静态命令表（id / 标题 / 别名 / 键位 / 回调），QML 只渲染与打分。

### 5.4 图表方案对比

| 方案 | 优点 | 风险 | 建议 |
|---|---|---|---|
| Qt Charts（`ChartView`） | 环形 / 折线 / 柱状开箱即用，图例、动画、tooltip 齐 | GPL 或商业双轨授权，闭源分发需买许可；样式难与设计稿逐像素对齐 | 报表页标准图先跑通 |
| QML 自绘（`Canvas` / `Shape`） | 完全贴合设计 token，体积小、性能可控 | 坐标轴、刻度、引导线全要自己做 | **推荐**首页小块图（预算环、火花线、堆叠条） |
| Qt Graphs（6.6+） | 官方新方向，基于 Quick 渲染 | API 仍在演进、资料少 | 观察，第一版不押注 |
| QCustomPlot / Qwt | 成熟、大数据量性能好 | Widget 与 QML 混排需桥接，主题割裂 | 重坐标轴交互时备选 |
| 内嵌 ECharts | 图表最丰富 | 拖入浏览器内核，包体与内存代价大 | 不建议 |

### 5.5 数据导入导出

- `.xlsx` 用第三方 MIT 库 QXlsx，**不要**用 `QAxObject` 调 Excel COM（用户未必装 Office）。
- 支付宝 / 微信账单是 CSV，常见 GB18030/GBK（部分版本带 UTF-8 BOM），必须嗅探编码再解码，否则中文摘要全乱；字段随版本变，要走**列映射**而非硬编码列序。
- 导入三步 UI：选文件 → 列映射 + 前 20 行预览 → 去重确认；去重键对 `(日期, 金额, 摘要)` 归一化后取哈希。
- 落库后立即跑"关键词 → 分类"规则库（星巴克→餐饮、滴滴→交通、房租→住房），可压掉大半人工分类。

### 5.6 自动备份

- 用 `VACUUM INTO` 或 `sqlite3_backup` 热备，**不要**直接复制 `.db`（WAL 下可能拷到半个事务）。
- 时机：启动、退出、每日定时各一次；保留最近 10 份 + 每月 1 份归档；目录 `%LOCALAPPDATA%\KeepAccount\backups`。
- 备份前 `PRAGMA wal_checkpoint(TRUNCATE)`，备份后 `PRAGMA integrity_check`；失败要给人话提示，不能静默。
- 金额以 int64「分」存储，不用浮点——这比任何 UI 细节都更影响信任。

## 6. 结论

- **只做一套就做 A**：三栏在 1440 宽屏信息效率最高，与 C++ Model/View 天然契合，右栏换图表即可演进成 C；反过来从 B/D 长成 A 几乎要重做。B 的圆角与 D 的暗色更适合作为 A 的皮肤或可选模式。
- **落地顺序**：A（骨架）→ D（录入路径，直接决定日活）→ C（统计页的说服力）→ B（差异化最弱，只在明确面向轻度用户时才做主方案）。
- **四套必须共享**：演示数据字典、账户与分类体系、金额排版规则、快捷键表。差异体现在布局与气质，而非数据口径。

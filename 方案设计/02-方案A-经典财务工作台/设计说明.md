# 方案 A · 经典财务工作台 — 设计说明

## 1. 定位与参考

**一句话定位**：把「记账」当成填一张财务台账——信息密度优先、每一列都可核对的专业记账器。

参考软件与借鉴点：

| 参考 | 借鉴点 |
|---|---|
| MoneyWiz 3（macOS/Windows） | 左侧导航 + 账户余额树、中间流水、右侧交易详情的三栏骨架 |
| 随手记 专业版 | 中文分类体系、月度 KPI 条、日期分组头与「今天」高亮 |
| Quicken（Windows） | 流水表的列结构（分类 / 摘要 / 账户 / 金额右对齐）与键盘流操作 |
| Excel 家庭账本 | 密集行高、等宽数字对齐、合计行与状态栏 |

设计目标是「看得清、对得上、改得快」：一屏内同时给出导航、关键指标、流水明细与单笔详情，不做滚动才发现数据的布局。

分区职责：

1. **标题栏 40px**：应用图标 + 账套名 + 账本年度 + 当前用户 + 46×40 三个窗口热区（关闭 hover 为 `#E81123` 红底白字）。
2. **工具条 56px**：月份切换（左右箭头 + 年月份）、全局搜索、筛选、自定义列、导出、主行动按钮「+ 记一笔」。月份切换放在最左侧，因为「看哪个月」是本产品的第一决策。
3. **左导航 248px**：6 个一级入口（工作台/流水/报表/预算/账户/设置，带计数徽标）→ 账户分组列表（5 个账户 + 实时余额，负债用红色负号）→ 本月支出分类 Top4（色点 + 金额）→ 底部预算卡（90.9% 紧张态用琥珀色）+ 快捷键提示。
4. **中栏 838px**：5 格 KPI（收入/支出/结余/预算已用带进度条/预算剩余）→ 列头 → 日期分组流水（分组头 28px 显示星期与当日小计，行高 45px）→ 状态条（可见条数 + 键盘提示）。
5. **右详情 352px**：选中交易的完整字段（金额、摘要、日期、账户、分类、备注）、标签 chips、本月同类统计卡、同类最近 3 笔、操作区（记一笔类似 / 复制 / 删除）与快捷键提示。

统计页（03-统计）信息架构：左导航 + 「统计分析」标题行（含分类/账户/标签/成员 视图切换）→ 5 格 KPI → 左 700px「支出分类排行表」（名次·分类·金额·占比·占比分布进度条 + 合计行）→ 右 444px「近 6 个月收支对比」分组柱状图 + 「本月预算执行」卡。

记一笔（02-记一笔）信息架构：主界面整体压暗 `rgba(15,18,24,.55)`，居中浮出 860×620 面板：左侧分类九宫格 + 付款账户 chips + 日期 + 备注；右侧金额显示 + 数字键盘 + 本月同类统计提示；底部「取消 / 保存并再记 / 保存」与 `Ctrl+Enter` 提示。

## 4. 交互与快捷键设想

| 快捷键 | 行为 | 备注 |
|---|---|---|
| `Ctrl + N` | 打开「记一笔」录入面板 | 全局最高频，任何页面可用 |
| `Ctrl + F` 或 `/` | 聚焦工具条搜索框 | `/` 仅在非输入态生效 |
| `↑` / `↓` | 在流水表中上下移动选中行，右侧详情实时联动 | 选中行左侧 2px 蓝色 inset 条 + 浅蓝底 |
| `Enter` | 打开当前选中交易的详情面板（或展开） | 连续按两次 `Enter` 进入编辑态 |
| `Tab` / `Shift + Tab` | 录入面板内 分类 → 金额 → 账户 → 日期 → 备注 循环 | 金额区聚焦时可直连数字键盘 |
| `Ctrl + Enter` | 保存并关闭录入面板 | `Ctrl + Shift + Enter` = 保存并再记一笔 |
| `Ctrl + D` | 复制选中交易（记一笔类似） | 复制后直接聚焦金额，只改数字即可 |
| `Delete` | 删除选中交易 | 二次确认，可撤销（Ctrl+Z） |
| `Ctrl + ←` / `Ctrl + →` | 切换上 / 下一个月 | `Ctrl + T` 回到本月 |
| `Ctrl + E` | 导出当前视图为 CSV | 导出范围 = 当前筛选结果 |
| `Esc` | 关闭录入面板 / 取消选中 / 退出编辑态 | 逐层回退 |
| 双击行内金额 | 就地编辑该笔金额 | 不打开完整表单，最省事 |

补充交互：

- 日期分组头可点击折叠 / 展开该日流水，折叠后计数显示在分组头右侧。
- 列头「金额」可点击切换升 / 降序；「分类」可点击切换为按分类分组。
- 左导航账户项 hover 显示「编辑 / 对账」小图标；预算卡 hover 显示「调整预算」。
- 窗口关闭按钮 hover 为 `#E81123` 红底白字，其余窗口按钮 hover 为 `#F2F3F5` 浅灰底。

## 5. 优点 / 缺点 / 最适合的人群

**优点**

1. **可核对性最强**：分类（文字 + 色徽标）、时间、摘要、账户、金额五列同行，任意一笔都能横向扫读核对，这是记账软件最核心的信任感来源。
2. **信息密度高**：1440×900 内同时呈现 5 个 KPI、11 条流水、5 个账户余额、4 类支出结构与单笔完整详情，不需要来回滚动。
3. **键盘友好**：三栏布局 + 上下键选择 + 右侧详情联动，让「批量核对上月流水」这类任务效率极高。
4. **品牌感克制**：只用一种强调色（#2563EB）与一套中性灰，长期使用不疲劳；预算紧张态用琥珀色而非刺眼红色，仍有预警力。
5. **实现成本低**：全部由矩形、1px 边框、8px 圆角与文字组成，无模糊 / 无复杂合成，QML 落地风险最小。

**缺点**

1. 视觉偏「冷」与「工具感」，首次打开对轻用户不够友好，学习成本高于卡片式方案。
2. 列多，窄窗口（< 1280）必须裁剪或折叠列，需要额外的响应式规则。
3. 「记一笔」入口只有一个按钮 + 一个快捷键，缺少「点一下就记」的快捷路径，录入摩擦略高。
4. 手机 / 平板端不可直接复用小屏布局，需要另做断点。

**最适合的人群**

25–35 岁、已养成记账习惯、每月会做一次对账与复盘、习惯键盘操作的上班族与自由职业者；也适合需要看「账户余额结构」的家庭账本用户。不适合只想快速记一笔、几乎不回看报表的轻度用户。

## 6. QML 实现要点与风险

### 6.1 建议的组件结构

```
ApplicationWindow (flags: Qt.FramelessWindowHint | Qt.Window)
└─ ColumnLayout
   ├─ TitleBar.qml          高度 40；MouseArea 拖动 → window.startSystemMove()
   ├─ ToolBar.qml           高度 56；月份切换 / 搜索 / 筛选 / 记一笔
   └─ RowLayout
      ├─ NavRail.qml        宽度 248；ListView（6 项）+ 账户分组 + 预算卡
      ├─ TransactionList.qml 宽度 838；KPI 条 + ListView(section) + 状态条
      └─ DetailPane.qml     宽度 352；绑定 ListView.currentItem
```

### 6.2 关键技术点

- **日期分组**：`ListView { section.property: "dateKey"; section.delegate: 28px 分组头; delegate: 45px 行 }`。行高固定即可开 `reuseItems`，180 条流水滚动依然 60fps。
- **选中联动**：`DetailPane` 直接绑定 `list.currentItem.tx`，避免二次查询 SQLite；`Keys.onUpPressed / onDownPressed` 改 `currentIndex` 即可。
- **键盘流**：`Shortcut { sequences: ["Ctrl+N"] }` + 面板内的 `KeyNavigation.tab`；`Ctrl+Enter` 用 `Keys.onPressed` 判断 `event.modifiers & Qt.ControlModifier`。
- **占比进度条**（统计页）：`Rectangle` 做轨道 + 内部 `Rectangle { width: parent.width * ratio }`，成本几乎为零，不要引入图表库。
- **柱状对比**：`Row` + `Repeater` + 每根柱子一个 `Rectangle`，高度 `model.value / maxValue * plotHeight`；需要动画时用 `Behavior on height { NumberAnimation }`。
- **自绘标题栏**：Qt 6.11 已有 `requestActivate()` 与 `startSystemMove()`，双击标题栏最大化需自己处理 `MouseArea.onDoubleClicked`；贴边分屏（Snap Layouts）需要通过 `Qt.WindowMaximized` 手动模拟，属于已知成本项。
- **数字对齐**：`font.features: { "tnum": 1 }`（Qt 6.7+）；低于该版本时给所有金额 `Text` 指定等宽字体族并右对齐。

### 6.3 风险与成本

| 项 | 风险等级 | 说明与对策 |
|---|---|---|
| 表格列宽固定 px | 中 | 130%/150% 系统缩放下需整体缩放；建议全部尺寸放进一个 `Theme.qml` 单例并按 `Screen.devicePixelRatio` 或用户缩放系数换算 |
| 11px 小字可读性 | 中 | 1x 下 11px 中文尚可，缩放后可能发虚；建议关键列头不小于 11px，且准备 12px 的「舒适密度」档 |
| 自绘标题栏拖拽 / 分屏 | 中 | 需自行实现拖动、双击最大化、右键系统菜单；可用 `Qt.FramelessWindowHint` + `startSystemMove()` 降低工作量 |
| 行内就地编辑 | 中 | 双击改金额需要 `Loader` 切换 `Text` ↔ `TextField` 并处理焦点抢占，建议先做只读 + 面板编辑，V2 再加就地编辑 |
| 选中行左侧 2px 蓝条 | 低 | 用 `border.left` 会改变布局宽度导致抖动；应在行内叠一个 `width:2` 的 `Rectangle` 或用 `layer` |
| 统计页柱状图 | 低 | 纯 `Rectangle` 组合即可，无需 QtCharts / QtGraphs（避免额外模块与包体） |

**总体结论**：本方案几乎不含高成本视觉效果，是四套方案里落地最快的；主要工作量在「表格虚拟化 + 键盘交互 + 列宽响应式」这三件工程事上，而不是视觉还原。

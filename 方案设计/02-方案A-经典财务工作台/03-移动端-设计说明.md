# 小满记账 · 移动端 App 原型设计说明

> 由「方案 A · 经典财务工作台」（桌面 1440×900）适配而来
> 画布：Ardot 文件「小满记账 · 移动端 APP 原型」 · 屏幕基准 393 × 852（iPhone 14/15）

---

## 1. 适配总原则：三栏变一列，键盘流变拇指流

桌面原型的骨架是「左导航 248 + 中栏流水 838 + 右详情 352」，它成立的前提是**宽屏 + 全键盘**。移动端只有 393pt 宽、没有悬停、没有 Tab 键，如果硬压缩三栏，结果是三栏都不可用。所以适配不是等比缩放，而是三件事的重新分配：

| 桌面能力 | 桌面实现 | 移动端替代 | 判断依据 |
|---|---|---|---|
| 一级导航（6 项） | 左侧 248px 纵向导航 | 底部 62px 胶囊标签栏 4 项 + 中央「记一笔」主按钮 | 拇指热区在下半屏；6 项压到 4 项，其余下沉为页面内入口 |
| 交易详情（352px 右栏） | 常驻右栏，随选中行联动 | 底部面板（bottom sheet）滑出，覆盖 66% 高度 | 空间换层级：详情是「临时看一眼」，不该常驻占用 1/3 屏宽 |
| 录入面板（860×620 居中浮层） | 模态浮层 + 数字键区 | 全屏页（88% 场景为单手竖屏录入） | 移动端键盘会顶起半屏，浮层会被压扁，全屏才能容纳「大类 + 小类 + 账户 + 数字键盘」 |
| 5 格 KPI 条 | 一行横排 | 3 格主指标 + 脚注行（日均 / 笔数 / 预算占比） | 393pt 放 5 格每格仅 71pt，金额会截断；次要指标降级为脚注 |
| 键盘快捷键（14 组） | Ctrl+N / ↑↓ / Enter / Ctrl+D | 手势与固定位置按钮：中央 FAB、行内点击、长按、左滑 | 移动端无键盘，需要等价操作路径，不能只是"删掉" |
| 列结构（分类/时间/摘要/账户/金额 5 列） | 表格 5 列同行 | 徽标 + 双行文本（摘要 / 分类·时间·账户）+ 右对齐金额 | 5 列在 393pt 必然截断；改为「主信息 + 元信息」两层，信息不丢失但不挤 |

**一句话**：桌面是「横向铺开、逐列核对」，移动是「纵向串起、逐笔确认」。

## 2. 视觉与信息架构的一致性约束

适配后仍严格沿用桌面原型的 Token，保证两端是同一个产品：

| 维度 | 桌面值 | 移动端用法 |
|---|---|---|
| 强调色 `accent` | `#2563EB` | 主按钮、选中态、今日分组头、金额强调。全屏**只有一处实心蓝**：中央「记一笔」 |
| 激活底 `accent.soft` | `#EAF1FF` | 导航激活（桌面左导航 → 移动标签栏激活项） |
| 画布 / 卡片 | `#F5F6F8` / `#FFFFFF` | 页面底色 / 卡片、列表底 |
| 次级 / 三级文字 | `#7A8290` / `#9AA1AC` | 副信息行、分组小计、字段标签 |
| 收入 / 支出金额 | `#15803D` / `#24292F` | 与桌面完全一致；仅负债与删除用 `#DC2626` |
| 预算紧张态 | `#FFFBEB` / `#FBE5B4` / `#B45309` | 首页预算卡、账户页还款提醒 |
| 10 个分类色 | 住房 `#6366F1`、购物 `#F59E0B`、餐饮 `#EF4444`、人情 `#EC4899`、教育 `#8B5CF6`、娱乐 `#06B6D4`、通讯 `#64748B`、日用 `#22C55E`、医疗 `#14B8A6`、交通 `#3B82F6` | 徽标、占比条、分类色点、排行进度条，四屏同源 |
| 圆角 | chip 4 / btn 6 / card 8 | 移动端按触控放大：chip 5–6 / 按钮 8–10 / 卡片 12（视觉比例不变） |
| 数字 | `tabular-nums` | 金额一律 Inter + 右对齐，保证同屏数字纵向对齐 |

**刻意保留的三处桌面特征**（识别度来源）：
1. **日期分组头**：`今天 · 11-12 周四 …… 支出 ¥297.00`，浅灰底 + 左侧蓝色今日标记，与桌面 `section.delegate` 一致。
2. **圆形分类徽标**：中文单字 + 分类色实心圆，是桌面 `.badge` 的直接延续。
3. **占比进度条**：桌面用 `Rectangle` 拼的纯色条，移动端沿用（不做圆环图），配色取自分类色。

**刻意不照搬的一处**：桌面导航激活态是实心蓝底，移动端改为「浅蓝底 + 蓝字」。因为移动端中央有一个实心蓝的「记一笔」主按钮，如果标签激活项也是实心蓝，屏上会出现两个同等权重的蓝块，主次就塌了。

## 3. 七个页面与关键流程

### 01 工作台（首页）— 对应桌面「工作台 + KPI 条 + 预算卡」
- **头部（白底）**：账本名 + 切换箭头、搜索、更多 → 月份大标题（20pt）+「本月」标记 → 三格 KPI（支出 / 收入 / 结余，各带一行说明）。
- **预算卡（琥珀）**：标题 + 「已用 90.9%」状态胶囊 + 大金额 `¥5,907.90 / ¥6,500.00` + 90.9% 进度条 + 「剩余 ¥592.10 · 接近超支」+ 右侧「调整预算」。与桌面左导航底部预算卡 1:1 复刻，但从角落提到首屏第二块，因为移动端用户打开 App 的第一诉求是「这个月还能花多少」。
- **支出构成卡**：一条 5 段占比条（住房 54.2% / 购物 26.5% / 餐饮 5.2% / 人情 3.4% / 其他）+ 2×2 图例（色块 + 分类 + 金额）。桌面的「左导航本月支出分类 Top4」在移动端没有位置，改成一条横条，信息量与「一眼看出结构」的目标都保住了。
- **最近流水卡**：日期分组头 + 3 行（徽标 / 摘要 + 分类·时间·账户 / 金额）+「全部 17 笔」。
- **底部**：胶囊标签栏 + 中央「记一笔」。

### 02 流水（账单列表）— 对应桌面「中栏流水表」
- **层级**：标题行（搜索 / 筛选图标）→ 月份切换器（`‹ 2026 年 11 月 ›`，整条可点，替代桌面工具栏的月份框）→ 类型筛选 chips（全部 / 支出 / 收入 / 转账 ｜ 账户 ▾）→ 汇总条（17 笔 · 支出 ¥5,907.90 ｜ 收入 ¥18,758.00）。
- **列表**：`28px 日期分组头 + 58px 流水行`。行内 4 个信息位：分类徽标、摘要（14pt Medium）、副信息「分类 · 时间 · 账户」（11pt 灰）、金额（右对齐、Inter SemiBold）。
- **桌面 5 列如何塞进 393pt**：分类列并入徽标、时间与账户并入副信息行、摘要升为主行，金额保持右对齐。5 个字段一个不少，但阅读次序从"横向扫"变成"纵向读".
- **交互**：点击行 → 05 详情面板；日期分组头可折叠（点一下收起当天）；下拉刷新；左滑单行出现「复制 / 删除」（对应桌面 `Ctrl+D` / `Delete`）。

### 03 记一笔（录入全屏页）— 对应桌面「02-记一笔」模态面板
自上而下五段，与桌面面板的左右分栏一一对应：

| 桌面区域 | 移动端 |
|---|---|
| 支出 / 收入 / 转账 分段 | 顶栏下方分段控件（32pt，白色滑块） |
| 右侧金额显示 + 数字键盘 | 金额区（`¥` + 38pt 数字 + 蓝色光标 + 「本月午餐已记 6 笔 · 均值 ¥28.60」）+ 底部 4×3 数字键盘（50pt 高、触控圈 8pt 间隙） |
| 左侧大类九宫格（4×2） | 5 列 × 2 行圆形分类格（10 类全部可见，选中项加 2px 蓝色描边 + 蓝色标签） |
| 左侧小类 chips | 横向滚动胶囊（早餐 / 午餐 / 晚餐 / 外卖 / 咖啡奶茶…） |
| 账户 chips / 日期 / 备注 | 明细卡三行：账户（右对齐值）/ 日期（`今天 · 11-12 周四 12:30`）/ 备注 |

- **关键决策：把数字键盘固定在底部常驻**，而不是「点金额才弹起」。因为记账的真实节奏是「先想到金额」——打开就是键盘，省掉一次点击。
- 顶栏右侧「保存」+ 关闭 X。桌面的「保存并再记一笔」下沉为保存后的轻提示（连续记账场景）。
- 触控尺寸：所有可点区域 ≥ 44×44pt（键盘 50、分类格整格 65×52 可点、chips 30 高但外扩热区）。

### 04 报表（统计分析）— 对应桌面「03-统计」
- 标题行 + 导出 → 月份切换器 → 视图切换（分类 / 账户 / 标签 / 成员，对应桌面同名 tabs）→ KPI 卡（3 列 + 脚注「日均支出 ¥591 · 17 笔 · 占预算 90.9%」）。
- **近 6 个月收支对比**：6 组双柱（支出实心蓝 9pt / 收入浅蓝 7pt），左侧 3 档刻度（2万 / 1万 / 0），当前月标签加粗高亮。桌面是 444px 宽的双柱图，移动端柱宽收紧但比例不变。
- **支出分类排行**：桌面是 5 列表格（名次 / 分类 / 金额 / 占比 / 进度条）。移动端压成两行式——首行「色标 + 分类名 + 占比 + 金额」，次行「进度条」。这样在 361pt 内既保住了排行语义，也让进度条获得完整宽度，比挤在 200px 里更可读。
- 桌面右侧的「本月预算执行」卡在移动端下沉：预算主信息已在 01 首页承担，报表页不再重复。

### 05 交易详情（底部面板）
- 触发：在 02 点任一行 → 背景压暗 `rgba(15,18,24,.45)` + 从底部滑出 564pt 面板（顶部 24pt 圆角 + 拖拽条）。
- 内容按桌面右详情栏顺序排列：分类徽标 + 分类名 + 「支出」标签 + 元信息「2026-11-11 周三 12:24 · 今日第 1 笔」→ 30pt 金额 → 摘要 → 账户 / 分类 / 备注 → 标签胶囊 → 「本月餐饮支出 ¥308.40 · 占比 5.2%」迷你卡 + 占比条 → 同类支出 2 笔 → 主按钮「记一笔类似」+ 复制 / 删除。
- 桌面右栏是「常驻、被动跟随选中」，移动端是「主动触发、看完即走」，所以操作按钮必须放在面板最底部（拇指最近处）。

### 06 账户
- 净资产卡：`¥30,896.87` 大数字 + 资产合计 / 负债合计两列（负债红色负号，沿用桌面 `acc-v.neg`）。
- 资产账户卡（4 行）+ 负债账户卡（1 行）：图标方块 + 账户名 + 「类型 · 尾号」+ 右对齐余额。
- 底部「+ 新增账户」+ 琥珀色「信用卡还款提醒」卡（桌面左导航的负债行只给了余额，移动端补一条时间维度提醒）。
- 桌面左导航的「账户余额树」在移动端升格为独立 Tab —— 因为账户结构是这套产品的核心资产，塞在侧栏里等于浪费。

### 07 分类管理
- 支出分类 / 收入分类 分段 → 分组标题「支出分类 · 10 个 · 长按可调整顺序」→ 10 行：色点 + 分类名 + 「N 个小类 · 房租 / 物业 / 水电 / 维修」+ 右对齐本月金额。
- 桌面没有独立分类管理页（分类在录入面板内新建），移动端把它独立出来，因为**小类会随时间膨胀**，需要一处可批量维护、可看每月产出的地方。行尾留出拖拽排序与左滑删除的空间（长按进入排序态）。

## 4. 三条关键流程

**A. 快速记一笔（最高频，目标 ≤ 8 秒）**
标签栏中央 FAB → 03 全屏页（金额已聚焦、键盘常驻）→ 输入金额 → 点分类格（大类）→ 可选点小类 → 保存。
桌面路径是 `Ctrl+N → 分类 → 金额 → Tab 账户 → Ctrl+Enter`；移动端把「金额」提到第一步，因为金额是最确定的输入，分类可以在看到候选后决定。

**B. 查一笔并改掉**
02 流水 → 月份切换 / 筛选 chips 收敛范围 → 点行 → 05 面板滑出 → 修改或「复制 / 删除」→ 下拉关闭面板，列表就地更新（不跳页、不重载）。

**C. 月底复盘**
01 首页看预算剩余与支出构成 → 进入 04 报表看分类排行与 6 个月趋势 → 点某分类下钻到 02 流水（分类已作为筛选条件带入）→ 逐笔核对。这条链路对应桌面的「报表 → 筛选 → 流水表 → 右详情」，移动端把「下钻」做成了筛选状态传递，而不是把三栏重新拼起来。

## 5. 窄屏布局与数据展示的 6 条硬规则

1. **一屏一个主意图**：首页=看预算，流水=找某笔，报表=看结构，账户=看余额。不在一屏塞两个目标。
2. **金额永远右对齐、永远等宽数字**（Inter + `tabular-nums`），保证纵向扫视时小数点对齐。
3. **列表行高 ≥ 56pt**：桌面 45px 行高在触屏上会误触相邻行；58pt 兼顾密度与命中率。
4. **单行信息不超过 3 个语义单元**：摘要 + 「分类·时间·账户」+ 金额；账户名过长时截断（`招商银行信用卡` 在副信息里允许省略为 `招行信用卡`）。
5. **卡片内不做横向滚动**，需要横向滚动的只有小类 chips 一行，并保留 12pt 露出的下一项作为可滚提示。
6. **表格 → 卡片的降级顺序**：先并列（5 列 → 2 行），再降字号（13 → 11），最后才折叠（Top5 + 展开）。不直接砍字段。

## 6. 落地建议

- **断点**：≤ 420pt 单列（本稿）；420–768pt 可恢复「列表 + 侧滑详情」；≥ 768pt 回归桌面三栏。三套布局共用同一套 Token 与数据模型，只是容器不同。
- **组件复用**：`AmountText`（等宽 + 对齐 + 正负色）、`CategoryBadge`（色 + 单字）、`DateGroupHeader`、`ProgressBar`（纯色）、`Segmented`、`BottomSheet`。这 6 个组件即可覆盖 7 个页面 90% 的视觉工作量。
- **图表零依赖**：柱状图与占比条全部用矩形拼（本稿即是），不引入图表库；10 个分类色 + 1 个中性灰足够表达所有占比关系。
- **性能**：流水列表用固定行高 + 复用池（对应桌面 `reuseItems`）；记一笔页的键盘常驻，避免焦点切换导致的布局抖动。
- **待补的真实细节**：左滑删除的二次确认、空态（本月无流水）、加载骨架、分类下钻时筛选 chip 的回显样式。

## 7. 与原桌面原型的差异清单（都是有意为之）

| 差异 | 原因 |
|---|---|
| 导航激活态：实心蓝 → 浅蓝底 | 把唯一的实心蓝让给「记一笔」主按钮 |
| 月份切换：工具栏方框 → 通栏切换器 | 移动端月份是第一决策，需要更大的点击面积 |
| 详情：常驻右栏 → 底部面板 | 屏宽不足，详情属临时信息 |
| 录入：浮层 → 全屏 | 软键盘占屏 40%，浮层会被压扁 |
| 预算执行卡：报表页 → 首页 | 首页才是"现在还能花多少"的场景 |
| 分类管理：面板内新建 → 独立页 | 小类会膨胀，需要可维护的落点 |

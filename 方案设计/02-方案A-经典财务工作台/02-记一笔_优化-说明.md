## 三、界面结构

```
┌ 记一笔 ── [支出 | 收入 | 转账] ───────────── Ctrl+Enter 保存 ── ✕ ┐
│ 支出大类（8 宫格）              │  金额 ¥28.00                     │
│ 小类（依赖大类，可新建）         │  本月「午餐」已记 6 笔 · 均值 ¥28.60 │
│ 账户（chips）                  │  数字键盘                        │
│ 时间：日期 + HH:mm + 快捷       │                                 │
│ 备注 + 标签                    │  本月餐饮（含小类）预算卡片        │
├─ 键位提示 ──────────────── 取消 / 保存 ────────────────────────┤
```

- **三段式切换**放最左（支出/收入/转账），切换后左列内容整体更换，右列只保留金额与键盘。
- **两级分类**：大类常驻，小类跟随大类；小类可留空（只记到大类）。
- **时间**：默认「现在」（精确到分钟，秒固定 00），历史补记可用「昨天/前天」或直接改数字；编辑时同样可改。
- **转账**：转账不选分类（避免与支出分类混淆），只选从/到账户；「转给他人」多出「对方」与「记作」两个字段。

## 四、关键交互 / 键盘流

| 操作 | 键位 | 说明 |
|---|---|---|
| 切换 支出/收入/转账 | `Tab` 或点击 | 转账态下分类区隐藏 |
| 选大类 | `↑ ↓ ← →` | 8 宫格方向键移动 |
| 选小类 | `← →`（在 chips 行内） | 回车确认；`N` 新建小类 |
| 时间微调 | `Alt+↑ / Alt+↓` | 每次 ±5 分钟；`T` 回到「现在」 |
| 保存 | `Ctrl+Enter` | 与现有行为一致 |
| 撤销编辑 | `Ctrl+Z` | 编辑态底部有提示 |

## 五、数据口径（**请重点确认**）

| 场景 | 存储 | 本月支出 | 收入 | 预算 | 账户余额 |
|---|---|---|---|---|---|
| 支出（可选小类） | `kind=expense`，`category_id` 指向**小类**（留空则大类） | ✅ 计入 | — | ✅ 计入（大类累计，小类下钻） | 该账户减少 |
| 收入 | `kind=income` | — | ✅ 计入 | 不计 | 该账户增加 |
| **本账本账户互转** | `kind=transfer`，`account_id`=转出，`to_account_id`=转入 | ❌ **不计** | ❌ 不计 | ❌ 不计 | 一减一增，总额不变 |
| **转给他人 · 记作支出（默认）** | `kind=expense`，分类「人情往来 › 借出」 | ✅ 计入 | — | ✅ 计入 | 转出账户减少 |
| **转给他人 · 记作借出** | `kind=transfer`，转入方为「应收 / 应付」往来账户 | ❌ 不计 | ❌ 不计 | ❌ 不计 | 转出账户减少，**应收资产增加** |
| 他人还款 | 反向：往来账户 → 本账本账户 | ❌ 不计 | ❌ 不计 | ❌ 不计 | 应收减少，账户增加 |

> 净资产口径：`应收` 计入资产、`应付` 计入负债；账户互转不影响净资产。

## 六、与当前实现的差距

**数据库层已具备（不需要迁移）**

- `transactions.kind` 的 CHECK 已包含 `'transfer'`，`to_account_id` 字段与「转账必须填转入账户」约束都已存在
- `transactions.occurred_at` 已是 `yyyy-MM-ddTHH:mm:ss`（秒已存，只是 UI 只让选日期）
- `categories.parent_id` + `UNIQUE(parent_id, name, kind)` 已支持小类
- 账户余额计算已包含转入/转出（`AccountRepository` 的余额表达式里已处理 `kind='transfer'`）
- 月度汇总/分类占比只统计 `income` / `expense`，转账天然不计入 → 与本次口径一致

**需要开发的部分**

1. 数据：为 8 个大类各 seed 5–8 个小类（首次运行播种，之后可在分类管理里改）
2. 数据：新增账户类型 `receivable`（应收）/ `payable`（应付）→ 需要一次迁移（重建 `accounts` 的 CHECK 约束，复用 V4 的重建流程）
3. 仓储：`TransactionRepository` 支持写入/查询转账（`to_account_id`），列表查询要把 transfer 关联出「从 → 到」
4. 视图模型：`addTransaction / updateTransaction` 增加 `timeText`、`subCategoryId`、`toAccountId`、`counterparty`、`transferNature` 参数
5. UI：重做 `RecordDialog.qml`（三段式 + 两级分类 + 时间选择 + 转账分支），并保持现有键盘流
6. UI：流水列表与详情面板显示转账行（「支付宝 → 招行」样式）与小类路径
7. 报表：分类排行支持「大类汇总 / 展开小类」切换（可选，建议二期）
8. 自检：新增断言覆盖 转账不计收支、净资产不变、应收增加、时间保存到分钟、小类落库

## 七、已确认的设计决策（2026-11-12 审核通过）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 「转给他人」的口径 | **支出 / 借出 二选一，默认「支出」** |
| 2 | 小类是否允许留空 | **允许**，只记大类的记录完全合法 |
| 3 | 时间精度 | **只到分钟**（秒固定 00） |
| 4 | 新增账户类型 | **新增「应收（receivable）」「应付（payable）」两种账户类型** |
| 5 | 转账的收支口径 | **转账面板提供「记作：支出 / 借出」开关**；支出计入预算，借出计入应收资产、不计支出 |

### 由决策衍生的实现要点

- 「记作 · 支出」时：`kind=expense` + 分类（默认 `人情往来 › 借出`）+ 可不选转入账户（仅作备注，不产生 transfer 记录）
- 「记作 · 借出」时：`kind=transfer` + `to_account_id` = 应收/应付往来账户；对方还款 = 反向 transfer
- 往来账户余额方向：应收（资产）为正、应付（负债）为负；净资产 = 普通账户 + 应收 − 应付
- 小类留空时 `category_id` 指向大类本身（不是 NULL），报表天然按大类累计
